- Handler is `(req: http.IncomingMessage, res: http.ServerResponse)`; may be `async` — the
  dispatcher **awaits** it.
- **The handler owns the full response lifecycle** (`:101-102` JSDoc: *"Route handlers retain
  direct response ownership."*). You must call `res.end()` yourself.
- Handler errors are caught: logged via `ctx.logger.warn`, then 400 if headers not yet sent,
  else `res.destroy()`. No try/catch needed for basic safety, but you still own the body.
- When nothing matches and no fallback is registered, the server writes **404**.
- Registered paths are matched on `pathname` only (query stripped, `:232`).
- There is **no CORS/body parsing/auth**: see `dsh-host-open-in-app/lib/index.js:1264-1270`
  for the `connectionOf(ctx).requestRejection(req)` idiom used by shipped routes.

`index.js` exports one of these forms; do not mix them:

- `export function apply(ctx, config) {}` with optional `export const inject = ['tools']` and `export const Config`.
